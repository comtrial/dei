# S09 — 매칭 실패 / 큐 만료

- **담당자**: B
- **route(파일)**: `app/(app)/match/failed.tsx`
- **목적**: 큐 등록 후 24h 내 매칭 안 됨 → 푸시 알림 + 앱 진입 시 이 화면. 사용자가 빈손으로 돌아가지 않도록 "왜 안 됐는지" + "다음 액션" 명시.

## 의존 DS 컴포넌트
- **Text** — 헤딩 "매칭 상대를 찾지 못했어요" · 설명 "큐가 24시간 만료됐어요. 다시 시작하면 새로운 인연을 찾아드려요."
- **IconButton** — CloseButton(우상단) → S05 홈 (`device.sQE .nav .x`)
- **EmptyBlob / StateView** — EmptyStateLayout(안내 아이콘 + 헤딩 + 설명, center body) (`device.sQE .body` flex column)
- **Card** — WhyBox / InfoCallout "왜 만료됐나요?"(제목 + 3 bullet 사유, 비난 톤 X, S07a `.why` 동일 패턴) (`.sQE .info`)
- **Button** — PrimaryCTA(accent solid) "다시 매칭 시작" (`.sQE .cta`) · TextLinkAction(secondary text link) "나중에 다시 시도" (`.sQE .later`)

## 의존 데이터 / 서버(L1) / 정책(L2)
- **데이터**: `match_queue`(등록 시각 + 24h 만료 상태) · 푸시 알림(만료 안내 — 신규 채널 9번) · 묶음 멤버 목록(과팅 만료 전원 통지)
- **서버(L1)**: 큐 만료 배치/스케줄러(24h 경과 큐 자동 만료) · 큐 만료 푸시 발송(개인 + 과팅 묶음 전원) · 재매칭 시작 RPC(만료 후 즉시 재등록 허용)
- **정책(L2)**: 큐 만료 = 24h(PRD 미명시, 가정 정책) · 큐 만료에는 24h 재매칭 제한 적용 X(자동 만료는 시스템 책임) · PRD §11 알림 9번 큐 만료 안내(신규 정책 필요)

## 발생 이벤트 (PostHog)
- 없음

## 주요 결정 (decisions)
- 큐 만료 = 24h. PRD 미명시(우리 가정). 무제한이면 운영 부담 + 사용자 묻혀버림. 24h가 dei 매시간 업로드 사이클과 정합. **[결정완료] 24h 만료 정책 유지**
- "왜 만료됐나요?" 박스로 사용자 학습 — 알고리즘 블랙박스 아닌 투명 안내. 단, 비난 톤 X("당신 잘못이 아니에요" 느낌)
- 2-CTA — primary "다시 매칭 시작" / secondary "나중에 다시 시도" → S05 홈
- 큐 만료에는 24h 재매칭 제한 적용 X — 자동 만료는 시스템 책임. 사용자가 곧바로 다시 시작 가능
- **[결정완료] 과팅 묶음 만료 → 멤버 전원 푸시** ("같이 신청한 매칭이 끝났어요. 다시 시작할까요?")
- 알림 채널 추가 필요 — PRD §11 알림 8종에 "큐 만료 안내" 없음. **[결정완료] 9번 항목으로 추가** (PRD v0.8 작업으로 누적)
