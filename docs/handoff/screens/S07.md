# S07 — 매칭 큐 대기 (홈 ② 매칭 중)

- **담당자**: B
- **route(파일)**: `app/(app)/queue.tsx`
- **목적**: 홈 3-state 중 ② 매칭 중 상태. 대기 시간이 2~6시간이라 사용자는 앱을 닫고 일상을 보냄 — 매칭 성사 신호는 푸시 알림이 사실상 유일한 채널. 이 화면은 큐에 들어가 있다는 상태 확인 + 취소 진입점일 뿐.

## 의존 DS 컴포넌트
- **PulseRing** — 대기 표시(펄스 애니메이션 + dei 코어 마크). radial-gradient + scale/opacity keyframe, animation-delay .7s 이중 링, center accent 코어 원.
- **Text** — 헤딩("곧 만날 사람들을 찾고 있어요") · 설명("앱을 닫아도 매칭되면 알림으로 알려드려요") · CenteredHeroLayout(세로 중앙 정렬 본문).
- **Card** — EstimateBox(평균 대기 시간 박스 "2 ~ 6 시간", bg-2 + r-md, uppercase 라벨 + tabular-nums 값).
- **IconButton** — 매칭 취소 FAB(우하단 floating, paper bg + line border + r-full) → S08.
- **AlertDialog** — 큐 등록 실패 alert(조건부) → S05 복귀.

## 의존 데이터 / 서버(L1) / 정책(L2)
- **데이터(스키마)**: `match_queue`(현재 큐 등록 상태, 큐 깊이) · 푸시 알림 토큰(매칭 성사 신호 채널).
- **서버(L1)**: 매칭 워커 B1(`match_succeeded_push_sent` 푸시 발송) · 큐 상태/평균 대기시간 조회(실시간 동적) · 큐 등록 실패 핸들링.
- **정책(L2)**: 대기 시간 = 서버단 동적 산출(큐 깊이·매칭 속도) · 큐 위치/단계 비노출 정책 · 큐 만료 24h(S09 트리거).

## 주요 결정 (decisions)
- 알림 권한이 이미 있어야 진입 — 거부는 S07a 차단.
- 큐 위치(N번째) 노출 X — 운영 로직이 단순 순번이 아니라 혼란만.
- splash → 이 화면 직행 — 매칭 중 상태로 앱 재진입 시.
- 화면을 켜둘 이유 없게 설계. "앱 닫아도 알림이 와요" 안심 톤.
- 매칭 취소는 우하단 fab → S08.
- 큐 등록 실패 시 alert + S05 복귀.
- 매칭 진행 단계 표시 안 함 — "대기 중" 단일 상태.
- [결정완료] 대기 시간 = 서버단 동적(실시간 큐 상태 기반: 현재 큐 깊이·매칭 속도). "2~6시간"은 mockup 예시값.

## 라우팅
