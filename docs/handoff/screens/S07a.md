# S07a — 알림 권한 필요 안내

- **담당자**: B
- **route(파일)**: `app/(app)/permission/notification.tsx`
- **목적**: 매칭 큐 등록 직전 알림 권한 거부 상태로 차단된 사용자에게 표시하는 조건부 게이트. 매칭 성사·업로드 알림·멘션 등 핵심 기능이 모두 알림에 의존하므로 권한 없이는 큐 등록 불가.

## 의존 DS 컴포넌트

- `IconButton` — CloseButton(우상단 원형 36px, bg-2) → S05 홈 복귀
- `PermissionGate` — center body 레이아웃(아이콘 + 헤딩 + 설명, flex column center)
- `Text` — 헤딩 "알림이 꺼져 있어요" / 설명 "매칭 결과를 알려드리려면 알림이 필요해요. 설정에서 켜주세요."
- `Card` — WhyBox / InfoCallout "왜 필요한가요?"(제목 + bullet: 매칭 성사 / 매시간 업로드 / 멘션 귓속말)
- `Button` — StackedCTA: primary "설정에서 알림 켜기"(시스템 설정 deep link) / secondary "나중에 하기"(S05 복귀)
- 상태바, 아이콘 배지(info-soft tint 원형 64px)

## 의존 데이터 / 서버(L1) / 정책(L2)

- **데이터**: 없음
- **서버(L1)**: 없음
- **정책(L2)**:
  - 알림 권한 = 큐 등록 hard gate (권한 없으면 등록 불가)
  - 재진입 시 매번 안내 (쿨다운 정책 없음)
  - 설정 deep link 복귀 후 큐 자동 진행 (deferred queue intent)

## 발생 이벤트 (PostHog)

- 없음

## 주요 결정 (decisions)

- 권한 요청 시점 = 매칭 큐 등록 직전 (iOS UX best practice)
- 첫 진입자는 OS 표준 다이얼로그 자동 표출 → 이 화면 안 보임. 거부 상태에서만 진입
- 큐 등록 자체 차단 — 알림 없으면 dei 작동 안 함
- 설정 deep link → 사용자가 켜고 돌아오면 자동으로 매칭 큐 진행 (다시 CTA 안 눌러도 됨)
- "나중에 하기" 후 재진입 — 매번 안내 (쿨다운 없음). 권한 없으면 매칭 불가가 본질이라 피로 우려보다 안내 우선
- "왜 필요한가요?" 박스로 매칭/업로드/멘션 의존성 명시
