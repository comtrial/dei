# S23 — 고객센터

- **담당자**: B
- **route(파일)**: `app/(app)/support.tsx`
- **목적**: S19 '고객센터'·'환불 요청'·S18 결제 실패 '고객센터 문의' → 진입. 인앱 간단 문의 폼 + 영업일 회신. 환불 요청은 분류 자동 선택. 인앱 또는 이메일 회신.

## 의존 DS 컴포넌트

- **TopNav** — 뒤로가기 + 타이틀 '고객센터' [필수]
- **Text** — 헤딩 '무엇이 궁금하신가요?' [필수]
- **Select / Chip** — 분류 선택(드롭다운 또는 칩, 미확정). 환불 요청 진입 시 readonly **Input** 으로 대체(ReadonlyClassificationField) [필수]
- **Textarea** — 내용 입력(최대 500자) + 글자 카운트 'N / 500'(CharCount) [필수]
- **Input** — 회신 이메일(선택, 미입력 시 인앱 회신) [필수]
- **Banner** — 회신 안내 'ℹ 영업일 N일 내 회신'(ReplyNote info-soft 박스) [필수]
- **BottomActionBar** — position 고정 CTA 바(opacity .4↔1 활성 토글)
- **Button** — CTA '보내기'(내용 입력 시 활성) [필수]
- 상태바 [필수]
- 제출 후 토스트 '문의를 받았어요'(@dei/ui 미보유 → 토스트 채널 별도 처리)

## 의존 데이터 / 서버(L1) / 정책(L2)

**데이터**
- `support_inquiries` 적재 — 분류 + 내용 + 회신 이메일 + 신고자 (테이블명 HTML 미명시)
- 본인 이메일 — 자동 입력 시도용(본인인증 시 이메일 미수집이라 비어있을 수 있음)

**서버(L1)**
- 문의 제출 엔드포인트 → 운영 큐 적재 (HTML 미명시)
- 인앱 알림 회신 경로 (이메일 미입력 시) (HTML 미명시)

**정책(L2)**
- 인앱 폼 단일 채널 정책 (이메일·카톡 연동 X)
- 분류 4종 enum (결제·환불 / 매칭 / 차단·신고 / 기타)
- 환불 요청 진입 시 분류 자동 선택 정책
- 내용 최대 500자 제한
- 영업일 N일 회신 정책 (mockup 예시: 2일)

## 발생 이벤트 (PostHog)

- `S23:support_form_opened`
- `S23:inquiry_submitted`

## 주요 결정 (decisions)

- 인앱 폼 단일 채널. 이메일·카톡 별도 연동 X (운영 부담 최소화)
- 3개 필드: 분류(선택) / 내용(필수) / 회신 이메일(자동 입력 가능)
- 분류: 결제·환불 / 매칭 / 차단·신고 / 기타 4개. 환불 요청은 분류 자동 선택
- 회신 이메일 본인인증 시 이메일 받지 않음 → 직접 입력. 미입력 시 인앱 알림 회신
- 영업일 N일 내 회신 안내
- 제출 후 토스트 + 자동 S19 복귀
