# S06 — 친구 초대 (팀 구성)

- **담당자**: B
- **route(파일)**: `app/(app)/team/new.tsx`
- **목적**: S05 "친구와 함께" CTA에서 진입. 초대자가 친구 닉네임을 검색·추가해 매칭 묶음(과팅 팀)을 구성. 모든 멤버가 사용 가능한(non-busy) 상태일 때만 큐 등록 가능. 본인 포함 최대 5명(8셀 분할 피드 상한과 정합: 우리 5 + 상대 3 = 8).

## 의존 DS 컴포넌트

- `TopNav` — NavBar (back + title + count pill, 3분할)
- `Badge` — CountPill ("N / 5", bg-2 배경 + r-full)
- `Input` — 닉네임 검색 입력 필드 (leading icon + filled, 0.5s debounce)
- `IconButton` — 검색 leading 아이콘
- `Card` — 검색 결과 카드 (닉네임 + 프로필 사진)
- `Avatar` — 검색 카드 / 멤버 칩 이니셜 (AvatarInitial)
- `Button` — "+ 추가" / BottomCTA "N명으로 매칭 시작"
- `Chip` — MemberChip (me: accent border + 배지 / busy: warn dashed / add: dashed ghost)
- `EmptyBlob` — 검색 결과 빈 상태 "그런 닉네임의 친구가 없어요"
- `Banner` — busy 안내 바 (warn-soft) / 초대 불가 안내 "초대할 수 없는 친구예요"
- `Text` — SectionLabel ("내 묶음", uppercase + letter-spacing) / 헤딩 / 서브 카피
- `BottomActionBar` — 고정 하단 CTA 컨테이너 (border-top, disabled 시 opacity)
- `AlertDialog` — 검색 네트워크 실패 / 큐 등록 실패(race-condition)

## 의존 데이터 / 서버(L1) / 정책(L2)

**데이터(스키마 테이블)**

- `users` / `profiles` — 닉네임 unique key, 프로필 사진
- `blocks` — 차단 관계 (양방향)
- `room_members` / `conversations` — busy 멤버 = 활성 방 보유 여부
- `match_queue` — 팀 묶음 등록

**서버 의존(L1)**

- 닉네임 검색 RPC/쿼리 (debounce 0.5s)
- 차단 관계 조회 (보복 보호 — 사유 비노출)
- 팀 큐 등록 RPC (큐 등록 직전 멤버 busy 재검증)

**정책 의존(L2)**

- 최대 5명 상한 (8셀 분할 피드 = 우리5 + 상대3)
- busy 판정 = 멤버가 다른 활성 방에 있는지 (room membership)
- 닉네임 unique 제약

## 발생 이벤트 (PostHog)

- `join_team_selected`
- `team_queue_registered`

## 주요 결정 (decisions)

- 닉네임 기반 직접 검색 (PRD §6). 친구 목록·연락처 동의 추천 없음
- 수락 절차 없음 — 추가하면 바로 묶음 포함 (PRD §6)
- busy 멤버 = 초대자가 직접 조정 (PRD §6). 자동 제외 X, CTA 비활성
- 본인 포함 최대 5명 (8셀 분할 피드 상한과 정합)
- 닉네임 unique key — 동명이인 없음
- 검색 결과 카드 노출 정보 = 닉네임 + 프로필 사진만. 나이·지역 등은 매칭 후 멤버 프로필에서 (보호)
- 닉네임 미존재 → "그런 닉네임의 친구가 없어요" 안내
- 차단 관계 → "초대할 수 없는 친구예요" 안내 (구체 사유 노출 X, 보복 보호)
- 검색 네트워크 실패 → alert + 재시도
- [결정완료] 최소 인원수 = 본인 1명도 가능. 진입 장벽 최소
- [결정완료] race condition = 큐 등록 직전 다른 방 진입한 멤버 발견 시 큐 등록 실패 alert + 묶음 화면 돌아가 재조정. 자동 제외 X
