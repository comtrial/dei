# S04 — 프로필 작성 (1/3) 기본 정보

- **담당자**: B
- **route(파일)**: `app/(onboarding)/profile/step1.tsx`
- **목적**: 본인인증 통과 직후 첫 진입. 멀티스텝 3단계 중 1단계 = 기본 정보(닉네임). 성별·생년월일은 본인인증 결과로 자동 채워지고 lock.

## 의존 DS 컴포넌트
- `Text` — 헤딩('닉네임을 알려주세요') / 서브카피('매칭 후에도 변경 가능해요') / 글자 카운트(N/10) / 검사 상태 메시지
- `ProgressBar` — 스텝 진행바(33% / 66% / 100%로 1·2·3단계 표현, S04/S04b/S04c 공유 primitive)
- `Input` — 닉네임 입력 필드
- `Spinner` — 닉네임 검사 중 상태 표시
- `Input` / `Select` — 성별·생년월일 lock 필드(locked 변형, 본인인증 자동)
- `Badge` — '🔒 본인인증 자동' 인라인 잠금 표시
- `Button` — 하단 고정 CTA '다음 (2/3)', 검사 통과 시에만 활성(비활성 변형 필요)

## 의존 데이터 / 서버(L1) / 정책(L2)
**의존 데이터**
- 본인인증 결과 성별·생년월일 (S03 root of trust, lock 표시)
- 닉네임 중복 조회 (profiles.nickname unique key, 0.5초 debounce)
- 닉네임 blocklist (욕설 필터 + 운영팀 수동 blocklist)
- 온보딩 진행 단계 저장 (재진입 시 마지막 단계 복원)

**서버(L1)**
- 닉네임 unique·blocklist 검사 엔드포인트(debounce 호출)
- 프로필 step1 저장 (닉네임 + 본인인증 자동필드 commit)
- 온보딩 단계 진행상태 저장

**정책(L2)**
- 닉네임 정책: 한글·영문·숫자, 특수문자·이모지 금지, 1~10자
- 닉네임 = 시스템 unique key 정책 (PRD §6 친구 초대 기반)
- 닉네임 변경 30일 1회 throttle 정책
- 성별·생년월일 변경 불가(본인인증 lock) 정책

## 발생 이벤트 (PostHog)
- `profile_step_completed` (F24 · 프로필 멀티스텝 3단계 start)
- `profile_photo_uploaded` (F24 · S04b 단계에서 발생하나 같은 멀티스텝 flow의 alt)

## 주요 결정 (decisions)
- 닉네임 = 시스템 unique key — PRD §6 과팅 친구 초대 기반
- 성별·생년월일 lock — 본인인증 결과 자동, 변경 불가
- '매칭 후에도 변경 가능' 헬퍼는 닉네임 한정
- 뒤로가기 없음 — 본인인증 완료라 못 돌아감, 헤더 `<` 제거
- CTA 비활성 조건 — 닉네임 비어있거나 중복일 때
- 부적절 닉네임 차단 — 자동 욕설 필터 + 운영팀 수동 blocklist 병행. 차단 시 '사용할 수 없는 닉네임이에요' 안내
- 가입 도중 앱 종료 → 재진입 시 마지막 저장 단계부터
- 닉네임 정책 — 한글·영문·숫자, 특수문자·이모지 X, 1~10자
- 닉네임 검사 = 입력 후 0.5초 debounce 자동. 별도 '중복 확인' 버튼 없음. 검사 중 spinner, 결과에 따라 ✓/✗ 아이콘 + 메시지
- 검사 상태 4가지: 입력 전(중립) / 검사 중(spinner) / 통과(✓ '사용 가능해요') / 거부(✗ '이미 사용 중이에요' or '사용할 수 없는 닉네임이에요')
- 닉네임 변경 빈도 = 30일 1회(남용·추적 회피 방지)
- PRD §7 멀티스텝·사진·신상 명시 = PRD v0.8 작업으로 누적
