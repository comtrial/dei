## 4. 디자인 시스템 `@dei/ui` (v4, HTML SSOT 그대로 구현)

신규 공유 패키지 `@dei/ui`. **HTML 값을 임의 변경 없이 그대로** 코드화.

> **DS 범위 (CRITICAL — D-04 강화):** 디자인 시스템은 `:root` v4 토큰에만
> 국한되지 않는다. **HTML 31개 화면 각각의 CSS(`.s01`~`.s23`)에 그려진 모든
> 시각 요소를 빠짐없이 DS 컴포넌트(primitive/pattern)로 환원한다.** 버튼·인풋
> 같은 명백한 것뿐 아니라 — 아바타 그라데이션, 8셀 그리드 셀, 칩/태그, 각종
> 배너(restrict/warn/danger/info), 시트 핸들, pulse ring, blur 오버레이,
> 진행바, notch/status bar, empty blob, compare 카드, 브랜드 전환 프레임,
> 멘션 자동완성, 카운트다운 배지 등 **화면에 등장하는 단 하나의 조각도 raw로
> 남기지 않는다.** 화면 개발자(B·C)가 "DS에 없어서 직접 스타일링해야 하는"
> 요소가 0이어야 D-04 강제(raw 스타일 금지)가 성립한다.
>
> 따라서 DS 구현 전에 **31개 화면 CSS 전수 추출 워크플로우**를 돌려 모든 시각
> 요소를 인벤토리하고(화면별 → 컴포넌트 환원 + 토큰 매핑), 중복 제거 후
> primitive/pattern 목록을 확정한다. 아래 4.2 목록은 **최소 골격**이며 전수
> 추출 결과로 확장된다.

- 리뷰 체크리스트 + CI lint 게이트로 강제

### 4.4 DS 완결성 검증 (Phase 2.5 산출물)

전수 추출의 목표는 **화면 개발자가 raw로 만들 요소 0**. 이를 검증 가능하게:

- `docs/handoff/_analysis/ds-element-coverage.md` — 31개 화면 × 모든 시각 요소
  매트릭스. 각 요소가 어느 `@dei/ui` primitive/pattern으로 커버되는지 1:1 매핑.
  커버 안 되는 요소 = DS 구현 누락(0이어야 함)
- 각 화면 핸드오프 헤더의 "의존 DS 컴포넌트"는 이 매트릭스에서 자동 도출 →
  개발자가 화면 열면 필요한 DS 컴포넌트가 전부 이미 존재함이 보장됨

## 5. 데이터 스키마 골격 (A-3, A 선제 고정)

### 5.1 거버넌스 규칙 (A 고정)

- PK: 전 테이블 `id uuid default gen_random_uuid()` (1:1 매핑 테이블은 `user_id` PK)
- FK: 사람→`auth.users(id) on delete cascade`, 방/팀 하위→부모 cascade, 결제·감사→`set null`
- RLS: 방 도메인은 `public.room_is_member(room_id, auth.uid())` security-definer 헬퍼 단일 게이트
- 차단: `chat_is_blocked_between` 패턴을 멤버 pairwise로 확장
- status: 자유 text 아닌 `check` 제약
- realtime: `room`/`room_member`/`message`만 publication + replica identity full
- mutation: 상태 전이는 Edge Function/RPC(security definer) 단일 경로, RLS는 방어선

### 5.2 테이블 골격 + 충돌 매트릭스

| # | 테이블 | 그룹 | status | RLS 게이트 | 작업자 R/W | 충돌 |
|---|---|---|---|---|---|---|
| 1 | `profile`(기존 확장) | 사용자 | — | 본인 W / auth read | A·B·C R, 온보딩 W | 🔴 |
| 2 | `auth_verification` | 신원 | provider/status | 본인 SELECT + service write | A R/W | — |
| 3 | `team` | 팀 | FORMING/READY/MATCHING/LOCKED/DISBANDED | `team_is_member` | A W, B R | — |
| 4 | `team_invite` | 팀 | PENDING/ACCEPTED/DECLINED/EXPIRED | 초대·피초대·멤버 SELECT, 수락 RPC | A W, B R | — |
| 5 | `match_queue` | 매칭 | WAITING/MATCHED/CANCELLED/EXPIRED | 팀멤버 본인큐, enqueue/dequeue RPC | B W, C R | — |
| 6 | `group_match` | 매칭 | ACTIVE/ENDED/CANCELLED | `group_match_is_member`, 생성 RPC | C W, B·room R | 🔴 |
| 7 | `match_member` | 매칭 | side A/B | 동일 match set SELECT | C W, room R | — |
| 8 | `room` | 방 | ACTIVE/ENDED/DELETED | `room_is_member` AND not-blocked, realtime | A·B·C R, 생성 RPC W | 🔴 |
| 9 | `room_member` | 방 | owner/member, left_at soft | 동일 room SELECT, 본인행 UPDATE | A·B·C R, 본인 W | 🔴 |

| 16 | `refund_ticket` / `audit` | 운영 | — | admin only | A/PM | — |

**충돌 핫스팟 (🔴):** `profile`(스키마 변경 A 승인 필수, 새 컬럼 멱등), `group_match`
(C 단독 소유), `room`/`room_member`(A가 `room_is_member` 헬퍼·RLS를 먼저 못박음),
`message`(방 채팅=A, @멘션 귓속말 경로 포함).

**DM 미구현(D-08):** `direct_message`는 이번 범위 밖. 단체 채팅 + @멘션 귓속말만.
DM은 나중에 별도 화면. 스키마에 placeholder도 두지 않음(완전 제거).
